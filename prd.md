# PRD: BeatYourself

**Версия:** 1.0  
**Дата:** 29 апреля 2026  
**Тип проекта:** Personal pet project (single-user web application)  
**Автор:** Разработчик/единственный пользователь

---

## 1. Обзор приложения и цели

### 1.1 Краткое описание
**BeatYourself** — это персональная веб-платформа для постановки и отслеживания амбициозных физических челленджей с элементами геймификации. Приложение помогает пользователю формировать привычку к регулярной физической активности через систему конкретных, измеримых целей с дедлайнами.

### 1.2 Проблема, которую решает продукт
Существующие фитнес-приложения (MyFitnessPal, Strava, Apple Health) предлагают либо абстрактные ежедневные цели, либо требуют подписку для расширенной функциональности, либо перегружены социальными функциями. Пользователь хочет:
- Ставить **кастомные** амбициозные цели ("100 км за лето", "50 000 шагов за день")
- Видеть **чёткий прогресс** к цели в любой момент
- Чувствовать **геймифицированное удовлетворение** от выполненных челленджей
- Иметь **полный контроль** над интерфейсом и данными
- Работать с приложением **бесплатно**

### 1.3 Цели проекта
1. **Основная цель:** создать персональный инструмент мотивации для формирования привычки к физической активности
2. **Дополнительные цели:**
   - Получить опыт работы с интеграцией внешних API (Strava, OAuth)
   - Создать продукт с продуманным UX в стиле современных SaaS
   - Использовать только бесплатные сервисы для деплоя и хранения данных

### 1.4 Метрики успеха
- Регулярное использование приложения автором (вход 5+ дней в неделю)
- Завершение хотя бы одного крупного накопительного челленджа в первый сезон
- Поддержание streak'а 14+ дней подряд

## 2. Целевая аудитория

### 2.1 Единственный пользователь
- **Профиль:** разработчик с опытом full-stack SaaS-разработки, владелец iPhone
- **Текущая ситуация:** на старте пути к физической форме, не использует фитнес-сервисы регулярно
- **Цель:** начать регулярно бегать и ходить, мотивируя себя через амбициозные челленджи
- **Устройства:** в первую очередь — iPhone (mobile-first), вторично — десктоп

### 2.2 Сценарии использования
1. **Утренний/вечерний чек-ин:** открыть приложение с телефона, посмотреть прогресс по активным челленджам и streak
2. **Запись активности:** после пробежки или прогулки — внести данные вручную или дождаться синхронизации со Strava
3. **Создание нового челленджа:** в начале недели/месяца/сезона — поставить новую амбициозную цель
4. **Просмотр истории:** посмотреть архив достижений, увидеть, сколько челленджей пройдено

## 3. Основные функции и функциональность

### 3.1 Функция: Аутентификация (OAuth)

**Описание:** Один авторизованный пользователь, вход через сторонний OAuth-провайдер.

**Технические требования:**
- OAuth 2.0 через Google или GitHub (рекомендуется Google для удобства на iPhone)
- Whitelist по email: только заранее указанный email имеет доступ
- Сессии управляются через JWT или session cookies (httpOnly, secure)
- Redirect на login при попытке доступа без сессии

**Acceptance criteria:**
- При первом заходе пользователь видит экран входа с кнопкой "Войти через Google"
- После успешного входа сессия сохраняется минимум 30 дней
- Email, не входящий в whitelist, получает отказ в доступе
- Все API-эндпоинты защищены middleware-проверкой авторизации

---

### 3.2 Функция: Управление челленджами

**Описание:** Создание, редактирование, завершение и архивирование челленджей двух типов.

**Типы челленджей:**

| Тип | Описание | Пример |
|---|---|---|
| **single_day** | Цель должна быть достигнута в рамках одного календарного дня | "50 000 шагов за один день" |
| **cumulative** | Сумма результатов за период должна достичь целевого значения | "100 км бега до 31 августа" |

**Поля челленджа:**

| Поле | Тип | Описание | Обязательное |
|---|---|---|---|
| `id` | UUID | Уникальный идентификатор | Да |
| `title` | string (max 100) | Название челленджа | Да |
| `description` | text (max 500) | Описание/мотивация | Нет |
| `type` | enum | `single_day` / `cumulative` | Да |
| `metric` | enum | `steps` / `distance_km` / `duration_min` / `runs_count` / `custom` | Да |
| `target_value` | float | Целевое значение | Да |
| `unit` | string | Единица измерения (км, шаги, мин, раз) | Да |
| `difficulty` | enum | `easy` / `medium` / `hard` | Да |
| `start_date` | date | Дата начала | Да |
| `end_date` | date | Дедлайн | Да |
| `status` | enum | `active` / `completed` / `failed` / `archived` | Да |
| `created_at` | datetime | Время создания | Да |
| `completed_at` | datetime | Время завершения | Нет |
| `color` | string (hex) | Цвет акцента карточки | Нет |
| `icon` | string | Имя иконки (lucide-react) | Нет |

**Acceptance criteria:**
- Пользователь может создавать неограниченное количество челленджей
- Несколько челленджей могут быть активны одновременно
- При создании пользователь сам выбирает уровень сложности (easy/medium/hard)
- Челлендж автоматически переходит в статус `completed`, когда сумма прогресса ≥ `target_value`
- Челлендж автоматически переходит в статус `failed`, когда `end_date` < сегодня и цель не достигнута
- Завершённые и проваленные челленджи попадают в архив (видны в профиле)
- Пользователь может редактировать активный челлендж (изменить дедлайн, описание)
- Пользователь не может изменить `metric` или `target_value` после создания (для честности данных)

**Technical considerations:**
- Подсчёт прогресса выполняется на стороне сервера на основе записей в таблице `activities`
- Для оптимизации можно кэшировать `current_value` в самой таблице challenges с пересчётом при изменении activities
- Background job (или cron) проверяет дедлайны и переводит просроченные челленджи в `failed`

### 3.3 Функция: Запись активности

**Описание:** Запись физической активности — ручная или автоматическая (через Strava).

**Источники данных:**

1. **Ручной ввод** — форма на сайте с полями:
   - Тип активности (бег, ходьба, другое)
   - Дистанция (км)
   - Длительность (минуты)
   - Шаги (опционально)
   - Дата
   - Заметка (опционально)

2. **Strava API** — автоматическая синхронизация:
   - Pull-модель: периодический запрос (cron, раз в час) к Strava API за новыми активностями
   - Push-модель (опционально, v2): Strava webhooks для получения уведомлений о новых активностях в real-time

**Поля activity:**

| Поле | Тип | Описание |
|---|---|---|
| `id` | UUID | Уникальный идентификатор |
| `source` | enum | `manual` / `strava` |
| `external_id` | string | ID активности в Strava (для дедупликации) |
| `activity_type` | enum | `run` / `walk` / `other` |
| `distance_km` | float | Дистанция в км |
| `duration_min` | float | Длительность в минутах |
| `steps` | integer | Количество шагов (если есть) |
| `activity_date` | date | Дата активности |
| `note` | text | Пользовательская заметка |
| `created_at` | datetime | Время записи в систему |
| `strava_data` | jsonb | Сырые данные от Strava (для будущих фич) |

**Acceptance criteria:**
- Форма ручного ввода доступна с дашборда (быстрый ввод) и со страницы активностей (полный ввод)
- Активности из Strava дедуплицируются по `external_id` (повторная синхронизация не создаёт дубликаты)
- При появлении новой активности автоматически пересчитывается прогресс всех затронутых активных челленджей
- Пользователь может редактировать или удалять записанные активности (оба источника)
- При удалении активности прогресс челленджей пересчитывается

**Technical considerations:**
- Strava API: OAuth 2.0 flow с refresh token (токены действуют ~6 часов)
- Лимиты Strava API: 200 req/15min, 2000 req/day — с большим запасом для одного пользователя
- Endpoint: `GET /api/v3/athlete/activities?after={timestamp}` для получения новых активностей
- Сохранять `last_sync_at` для следующего запроса

**Документация Strava API:** https://developers.strava.com/docs/reference/

### 3.4 Функция: Дашборд (главная страница)

**Описание:** Центральный экран приложения, показывающий ключевую информацию для ежедневного использования.

**Структура дашборда (mobile-first, сверху вниз):**

1. **Streak-блок** (приоритет 1) — крупно, с акцентом
   - Число дней подряд активности
   - Иконка огня 🔥
   - Подпись "дней подряд"
   - "Активный день" = день, в котором есть хотя бы одна запись активности (любой источник)

2. **Активные челленджи** (приоритет 2) — список карточек
   - Каждая карточка: название, прогресс-бар, текущее/целевое значение, дней до дедлайна
   - Цветовая индикация по difficulty (easy = зелёный, medium = жёлтый, hard = красный)
   - Тап на карточку → детальная страница челленджа

3. **Быстрый ввод данных за сегодня** (приоритет 3) — форма
   - Кнопка "Добавить активность" → открывается модалка/bottom sheet
   - Опционально: виджет воды (+250 мл), виджет веса

4. **Календарь активности** (приоритет 4) — heatmap в стиле GitHub
   - Последние 90 дней (или 365 на десктопе)
   - Цвет ячейки зависит от количества активности в этот день
   - Тап на ячейку → детали дня

5. **Последние достижения** (приоритет 5) — лента
   - Карусель/список последних 3-5 завершённых челленджей
   - Бейдж с уровнем сложности и датой завершения

**Acceptance criteria:**
- Дашборд полностью адаптирован для экранов от 360px (mobile) до 1920px (desktop)
- Все данные дашборда загружаются одним API-запросом (`GET /api/dashboard`) для скорости
- Streak обновляется автоматически каждую полночь и при добавлении новой активности
- Прогресс-бары анимируются плавно (200-400 мс) при изменении значений
- Streak обнуляется, если за прошлый день нет ни одной записи активности

### 3.5 Функция: Трекер воды

**Описание:** Учёт ежедневного потребления воды.

**Поля water_log:**

| Поле | Тип | Описание |
|---|---|---|
| `id` | UUID | Уникальный идентификатор |
| `amount_ml` | integer | Объём в мл |
| `logged_at` | datetime | Время записи |

**Дополнительные настройки (user_settings):**
- `water_daily_goal_ml` (default: 2000) — дневная цель
- `water_default_portion_ml` (default: 250) — размер по умолчанию для быстрых кнопок

**UI:**
- **Виджет на дашборде:** круговой индикатор с заполнением (выпито/цель), кнопки быстрого добавления (+250 мл, +500 мл)
- **Отдельная вкладка "Вода":** график потребления воды по дням за последние 30/90 дней, история записей, настройка дневной цели

**Acceptance criteria:**
- Пользователь может добавлять воду в один тап с дашборда
- На отдельной странице видна история и тренд потребления
- Виджет обнуляется в полночь
- Можно удалить ошибочную запись

### 3.6 Функция: Трекер веса

**Описание:** Учёт изменения веса со временем.

**Поля weight_log:**

| Поле | Тип | Описание |
|---|---|---|
| `id` | UUID | Уникальный идентификатор |
| `weight_kg` | float | Вес в кг |
| `measured_at` | date | Дата измерения |
| `note` | text | Заметка (опционально) |

**UI:**
- **Виджет на дашборде:** последний вес, дельта от предыдущего измерения (▲ +0.3 кг или ▼ -0.5 кг), мини-график тренда
- **Отдельная вкладка "Вес":** полный график за всё время / 30 / 90 / 365 дней, история записей, опциональная цель веса (целевой вес + дата)

**Acceptance criteria:**
- Не более одной записи веса в день (при повторном вводе — обновление существующей)
- График отображается с интерполяцией пропущенных дней
- Виден общий тренд (среднее за 7 дней) поверх ежедневных измерений
- Возможность отметить целевой вес и видеть прогресс к нему

### 3.7 Функция: Профиль и архив достижений

**Описание:** Личная страница со статистикой и историей.

**Содержание:**
- Аватар (из Google OAuth) и имя
- Общая статистика: всего активностей, общая дистанция, общее количество шагов, общее время
- Текущий streak и максимальный streak
- **Архив челленджей:**
  - Завершённые (вкладка): сетка/список карточек с бейджами по difficulty
  - Проваленные (вкладка): отдельный список с возможностью увидеть, сколько % было пройдено
  - Фильтры по году и сложности
- Кнопки: "Подключить Strava" / "Отключить Strava", "Выйти"

**Acceptance criteria:**
- Каждый завершённый челлендж показывается с датой завершения и итоговым результатом
- Бейджи имеют визуальное различие по difficulty (бронзовый/серебряный/золотой или цветовая схема)
- Статистика пересчитывается на основе всех записей activities

### 3.8 Функция: Интеграция со Strava

**Описание:** Подключение аккаунта Strava и синхронизация активностей.

**Flow подключения:**
1. Пользователь нажимает "Подключить Strava" в профиле
2. Redirect на Strava OAuth: `https://www.strava.com/oauth/authorize?client_id=...&scope=read,activity:read_all`
3. Strava redirect обратно с `code`
4. Backend обменивает `code` на `access_token` + `refresh_token`
5. Сохранение токенов в БД (зашифрованные)
6. Запуск первичной синхронизации (импорт активностей за последние 30 дней)

**Синхронизация:**
- Cron-задача каждый час: запрашивает у Strava новые активности с `last_sync_at`
- Каждая активность сохраняется в `activities` с `source = 'strava'`
- Если refresh_token истёк или отозван — уведомление пользователя в UI

**Acceptance criteria:**
- Пользователь может подключить и отключить Strava в любой момент
- При отключении Strava-активности остаются в системе (не удаляются)
- Дубликаты не создаются благодаря `external_id`
- При ошибке синхронизации в UI показывается уведомление

**Technical considerations:**
- Регистрация приложения: https://www.strava.com/settings/api
- Хранение токенов: шифрование через AES-256 с ключом из переменных окружения
- Rate limiting на нашей стороне: не более 1 запроса в минуту к Strava

## 4. Рекомендации по техническому стеку

### 4.1 Frontend

**Рекомендация: Next.js 15 (App Router) + TypeScript + Tailwind CSS + shadcn/ui**

| Технология | Обоснование |
|---|---|
| **Next.js 15** | Full-stack фреймворк — frontend + backend в одном проекте, что упрощает деплой. App Router, Server Components, отличная производительность. Бесплатный деплой на Vercel или Render. |
| **TypeScript** | Типизация снижает количество багов, особенно в моделях данных (challenges, activities). Стандарт для современной web-разработки. |
| **Tailwind CSS** | Идеально для быстрой разработки и кастомного дизайна в стиле Claude. Легко поддерживать темизацию (light/dark). |
| **shadcn/ui** | Набор готовых стильных компонентов в духе минимализма Claude. Не библиотека, а копируемые компоненты — полный контроль. |
| **Framer Motion** | Для плавных анимаций прогресс-баров, переходов между страницами, анимаций streak'а. |
| **Recharts или Chart.js** | Для графиков веса, воды, активности (mobile-friendly, легковесные). |
| **lucide-react** | Иконки в стиле shadcn/ui — минималистичные и красивые. |

**Альтернативы:**
- **Vite + React + Express** — раздельный frontend/backend. Плюсы: проще понять разделение. Минусы: два деплоя вместо одного, больше boilerplate.
- **SvelteKit** — компактнее и быстрее, но экосистема меньше, и опыт переноса знаний на другие проекты ниже.

### 4.2 Backend

**Рекомендация: Next.js API Routes + Prisma ORM**

API Routes (Server Actions / Route Handlers) интегрированы в Next.js — не нужен отдельный сервер. Prisma — типобезопасный ORM с отличной интеграцией с TypeScript.

**Альтернатива:** отдельный Node.js (Fastify) backend — если хочется чёткого разделения. Но для одного пользователя избыточно.

### 4.3 База данных

**Рекомендация: PostgreSQL на Neon или Supabase (free tier)**

| Сервис | Free tier | Плюсы |
|---|---|---|
| **Neon** | 0.5 GB storage, 191 compute hours/мес | Serverless PostgreSQL, мгновенный старт, отличная интеграция с Vercel/Render |
| **Supabase** | 500 MB БД, 2 проекта, 50K monthly active users | Помимо PostgreSQL даёт Auth, Storage, Realtime — может пригодиться позже |

**Для этого проекта:** Neon — проще и быстрее, не нужны дополнительные фичи Supabase.

**SQLite не рекомендуется**, потому что Render Free Tier не имеет персистентного диска — данные будут теряться при рестарте контейнера.

### 4.4 Аутентификация

**Рекомендация: Auth.js (NextAuth v5)**

Стандартное решение для Next.js. Поддерживает Google OAuth из коробки. Реализация — буквально 30 строк кода. Whitelist по email легко добавляется в callback.

### 4.5 Деплой и хостинг

**Рекомендация:**
- **Web app:** Render (Free Web Service) или Vercel (Hobby plan)
- **БД:** Neon (free tier)
- **Cron-задачи:** Render Cron Jobs (бесплатно) или GitHub Actions (бесплатно для публичных репо)
- **Self-ping:** UptimeRobot (бесплатный мониторинг с пингом каждые 5 минут) — предотвращает засыпание Render

**Сравнение Render vs Vercel:**

| Критерий | Render | Vercel |
|---|---|---|
| **Free tier** | 750 часов/мес web service, засыпает через 15 мин | Hobby plan, не засыпает |
| **Cron** | Встроенный (бесплатный) | Не во всех free tier |
| **Холодный старт** | ~30-60 сек | Серверные функции запускаются быстро |
| **Лимит на серверные функции** | Полноценный сервер | 10 сек для Hobby (может быть проблемой) |

**Итоговая рекомендация:** **Render** — единый сервер удобнее для cron-задач, и pet-проект не упрётся в лимиты.

### 4.6 Дополнительные сервисы

- **Sentry (free tier)** — мониторинг ошибок (5K событий/мес бесплатно)
- **GitHub Actions** — CI/CD (тесты, линтинг при push)

### 5.4 Алгоритм подсчёта прогресса челленджа

```
function calculateProgress(challenge):
  if challenge.type == 'single_day':
    # Берём максимум за один день в периоде челленджа
    return MAX(
      SUM(activity[metric]) GROUP BY activity_date
      WHERE activity_date BETWEEN challenge.start_date AND challenge.end_date
    )
  
  if challenge.type == 'cumulative':
    # Суммируем все активности в периоде
    return SUM(activity[metric])
      WHERE activity_date BETWEEN challenge.start_date AND challenge.end_date
```

## 6. Принципы UI-дизайна

### 6.1 Визуальный стиль

- **Inspiration:** интерфейс Claude (claude.ai) — минимализм, тёплые серые тона, типографика, пространство
- **Тема:** светло-серая (`#f7f7f5`-ish background, не чисто-белый), тёплые оттенки серого
- **Акцентный цвет:** один основной (например, тёплый коричневый/терракотовый в духе Claude `#C96442` или нейтральный графитовый), используется ОЧЕНЬ дозированно — для CTA, активных состояний, индикаторов прогресса
- **Типографика:** sans-serif (Inter, Geist, или системный шрифт), хорошие размеры и spacing
- **Границы:** мягкие, тонкие, низкоконтрастные (`#e5e5e5`)
- **Углы:** скруглённые (8-12px для карточек, 6px для кнопок)
- **Тени:** очень мягкие или вообще без них

### 6.2 UX-принципы

1. **Mobile-first:** всё проектируется сначала под 375-390px (iPhone), потом адаптируется
2. **One-thumb usage:** ключевые действия (быстрый ввод, отметка воды) доступны нижней частью экрана
3. **Без лишних кликов:** добавление воды и активности — в 1-2 тапа
4. **Информативный, но не перегруженный дашборд:** каждый блок имеет чёткое назначение
5. **Обратная связь:** все действия дают мгновенный визуальный фидбек (анимация, изменение цвета)

### 6.3 Анимации

- Прогресс-бары: плавная анимация при изменении (Framer Motion `animate` prop)
- Переходы между страницами: subtle fade или slide (200-300 мс)
- Streak: лёгкая пульсация иконки огня при увеличении
- Завершение челленджа: confetti или scale-эффект на бейдже
- Hover-состояния (на десктопе): subtle scale или backdrop change

### 6.4 Адаптивность

| Breakpoint | Особенности |
|---|---|
| `< 640px` (mobile) | 1 колонка, нижняя навигация, bottom sheet для модалок |
| `640-1024px` (tablet) | 2 колонки на дашборде, sidebar появляется |
| `> 1024px` (desktop) | Полная sidebar-навигация, многоколоночный дашборд |

### 6.5 Структура навигации

## 7. Соображения по безопасности

### 7.1 Аутентификация и авторизация
- OAuth 2.0 через Google (NextAuth.js)
- Whitelist по email на уровне Auth callback
- httpOnly secure cookies для сессии
- CSRF-защита (встроена в NextAuth)
- Refresh-токены OAuth-провайдера в БД (опционально)

### 7.2 Защита данных
- Все API-эндпоинты требуют валидной сессии
- Validation на уровне API: Zod-схемы для всех входных данных
- Rate limiting на чувствительные эндпоинты (rate-limiter-flexible или Upstash Ratelimit)
- Параметризованные запросы через Prisma (защита от SQL-injection из коробки)

### 7.3 Strava-токены
- Шифрование `access_token` и `refresh_token` перед сохранением в БД (AES-256-GCM)
- Ключ шифрования — в переменных окружения (Render secrets)
- Refresh-токенов запрашиваем по необходимости

### 7.4 Переменные окружения
Никогда не коммитить:
- `DATABASE_URL`
- `NEXTAUTH_SECRET`
- `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET`
- `STRAVA_CLIENT_ID` / `STRAVA_CLIENT_SECRET`
- `ENCRYPTION_KEY`

### 7.5 HTTPS
- Render и Vercel предоставляют HTTPS из коробки — никаких дополнительных настроек

### 7.6 Логирование
- Не логировать токены, email, личные данные
- Sentry для ошибок с фильтрацией PII

## 9. Потенциальные проблемы и способы их решения

| Проблема | Риск | Решение |
|---|---|---|
| **Холодный старт Render Free Tier (30-60 сек)** | Средний — раздражает при ежедневном использовании | UptimeRobot или cron-job.org пингуют каждые 5-10 минут, поддерживая сервер активным |
| **Strava API: истекли токены** | Высокий — синхронизация ломается | Реализовать refresh flow с graceful fallback. UI-уведомление, если refresh не удался → запрос повторного подключения |
| **Strava webhook (если будет реализован) не поддерживается на Render free** | Низкий — pull-модель и так работает | Использовать polling вместо webhooks на v1; webhook'и — оптимизация на v2 |
| **Дубликаты активностей при сбоях синхронизации** | Средний — портит данные | Уникальный индекс на `(external_id, source)` в БД, на уровне приложения — upsert вместо insert |
| **Streak обнуляется в неудобный момент (например, болезнь)** | Низкий — демотивирует | Опциональная фича: "freeze days" (1-2 в месяц), которые сохраняют streak. Реализовать в v1.1 |
| **Прогресс не обновляется в реальном времени** | Низкий — пользователь видит старое значение | Server Components + revalidatePath или React Query с invalidation после mutations |
| **БД Neon упирается в лимит compute hours** | Низкий — для одного пользователя редко | Free tier 191 часов/мес — с большим запасом для одного юзера. Если упрёмся — план $19/мес или переход на Supabase |
| **Confetti-анимация лагает на старом телефоне** | Низкий — UX | Использовать легковесную библиотеку (canvas-confetti), отключать при `prefers-reduced-motion` |
| **Self-ping Render формально нарушает ToS** | Низкий — но есть | Использовать внешний сервис (UptimeRobot) — это уже "легитимный мониторинг" |
| **OAuth callback не работает на проде** | Средний — блокирует вход | Точно прописать redirect URIs в Google Console для production-домена. Тестировать сразу после деплоя |

## 12. Глоссарий

- **Челлендж (Challenge)** — пользовательская цель с дедлайном и измеримым результатом
- **Активность (Activity)** — единичная запись физической активности (пробежка, прогулка)

- **Cumulative челлендж** — цель, которая накапливается за период
- **Difficulty** — уровень сложности челленджа (easy/medium/hard), задаётся пользователем
- **Heatmap** — календарная визуализация активности по дням (как на GitHub)
- **PWA** — Progressive Web App, веб-приложение, которое можно установить на телефон
