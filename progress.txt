## 2026-04-30 — TASK-003: zod-validated env config

Status: done

What was already in place from a prior partial iteration (uncommitted):
- beatyourself/config/env.ts with a hand-rolled regex parser for the repo-root .env.local
- beatyourself/instrumentation.ts that imports config/env in NEXT_RUNTIME==='nodejs'
- /.env.example at repo root with placeholders (DATABASE_URL, NEXTAUTH_*, GOOGLE_*,
  ALLOWED_EMAIL, STRAVA_*, ENCRYPTION_KEY, CRON_SECRET; SENTRY_DSN commented)

What I changed in this iteration:
- Replaced the custom .env.local reader with @next/env's loadEnvConfig() pointed at the
  repo root (path.resolve(process.cwd(), "..")). Reasons:
    * Standard Next.js dotenv pipeline (multiline values, $VAR expansion, all .env.* tiers).
    * Eliminates a brittle 25-line regex parser.
    * Keeps the .env.local at the repo root (user's choice — .env.local has Neon DATABASE_URL,
      NEXTAUTH_SECRET, GOOGLE OAuth creds, ALLOWED_EMAIL).
- Added @next/env@16.2.4 as an explicit dep in beatyourself/package.json (was a transitive of
  next, but importing it directly warrants making it explicit).
- Added a coerceEmptyToUndefined() pass over process.env before zod safeParse. Optionals
  (STRAVA_*, ENCRYPTION_KEY, CRON_SECRET, SENTRY_DSN) are .optional() so empty .env values
  must read as undefined, not "" — otherwise the min-length checks fire on blank fields and
  break first-time setup. This mirrors common dotenv-zod patterns.

Test_steps (all verified by running `npm run dev` from beatyourself/):
1) Missing DATABASE_URL — `DATABASE_URL= NEXTAUTH_URL=http://localhost:3000 npm run dev`
   -> instrumentation hook throws with "DATABASE_URL: expected string, received undefined".
2) Invalid URL — currently the user's .env.local has a typo
   `NEXTAUTH_URL="http://localhost:3000""` (extra trailing `"`). Without override, dev fails
   with "NEXTAUTH_URL: Invalid URL". This is the live demonstration of test_step #2.
3) TypeScript types — env.ts exports `env: z.infer<typeof envSchema>`. `npm run typecheck`
   is clean; any server-side import of `@/config/env` (or relative path) gets fully typed env.

All checks pass (npm run typecheck / lint / format:check / build).
