1. Проблемы с валидацией окружения и конфигурацией (TASK-003, TASK-005)
Опечатки в локальном .env.local: В файле конфигурации есть синтаксические ошибки (лишняя кавычка в NEXTAUTH_URL="http://localhost:3000"" и проблема на строке 31). Из-за этого при каждом запуске автоматизированных тестов или скриптов приходилось обходить этот файл (shell-overridden env vars), иначе приложение падало с ошибками валидации zod.
Не работает валидация при старте в Next.js 16 (Turbopack): В задаче TASK-003 ожидалось, что при отсутствии переменных окружения приложение будет падать сразу при запуске (npm run dev). Однако в логах (в TASK-005) выяснилось, что instrumentation.ts в связке с Turbopack не запускается при старте так, как это было в Webpack. Валидация происходит «лениво» — только при первом обращении к БД или сервису. Это нарушает принцип "Fail Fast" на старте.
2. "Слепое пятно" в авторизации (TASK-007, TASK-008)
Отсутствие реального end-to-end тестирования OAuth: Весь код для входа через Google OAuth (NextAuth v5), проверки whitelist-email и создания пользователей написан, но он ни разу не тестировался в браузере. Автономный агент физически не мог пройти флоу редиректов Google. Существует высокий риск того, что при попытке реального входа возникнут проблемы (например, из-за несовпадения NEXTAUTH_URL или настроек Google Cloud Console).
3. Технический долг: Дублирование кода (TASK-013, TASK-014, TASK-023, TASK-024, TASK-031)
Функция плюрализации дней (pluralizeDays): Логика склонения русских слов ("1 день", "2 дня", "5 дней" с учетом исключений 11-14) была скопирована и вставлена как минимум в 4 разных компонента (ChallengeCard, StreakBlock, ActiveChallengesList, Profile). Это прямое нарушение принципа DRY (Don't Repeat Yourself), и функцию давно пора вынести в общий файл lib/utils/text-plural.ts.
Дублирование констант в формах: Настройки пресетов цветов, иконок и лейблов сложности (COLOR_PRESETS, ICON_PRESETS, DIFFICULTY_LABEL) дублируются между формой создания (ChallengeForm) и формой редактирования (EditChallengeForm).
4. Жесткая привязка к часовым поясам (TASK-013, TASK-021, TASK-027)
Несмотря на то что вы заложили отличную базу для поддержки разных часовых поясов (функции принимают userTz), в данный момент везде жестко захардкожено значение DEFAULT_USER_TZ='Europe/Moscow', либо используется серверное время UTC (в отображении дедлайнов челленджей). В модели UserSettings так и не появилось поле timezone, что делает приложение не совсем корректным для использования в других часовых поясах без доработки.
5. Предупреждения от React Compiler (TASK-014, TASK-018)
В компонентах форм (ChallengeForm, ActivityForm) используется метод form.watch() из react-hook-form. В логах сборки Next.js стабильно выдает предупреждения (warnings), так как React Compiler (поставляемый с Next 15/16) не может безопасно мемоизировать функцию watch. Это не ломает приложение, но сильно засоряет логи CI/CD.
